# HustMCL 四页界面方案（Campus Desk 原生演示）

状态：Campus Desk 方向已由用户选定，首页与安装页已实现为 Qt 6 Widgets 原生演示；设置、日志、真实认证与下载尚未实现。最新基线：`f134e1a`。

本轮在 DSH 中完成了 `src/application` 最小快照契约、`src/ui` 原生页面与共用组件、`src/app` 组装与显式演示控制器，并用 Qt 6.10.3 + MinGW 13.1 实际构建、运行和截图。MSVC 工具链仍未安装成功；桌面演示不是发布包，也没有真实后端。设计与素材来源见[华小科素材与背景设计](华小科素材与背景设计.md)。

## 1. 方向与实现结论

- 用户已选定 **Campus Desk / 校园工作台**。三个方向的对比页仍保留作历史研究，不再等待用户选择。
- Oil UI 仅用于前一轮方向探索与质量自审；本轮的交付是原生 C++ Qt Widgets，不是 HTML / SVG 页面。
- 首页从“多卡片仪表盘”收敛为**一张桌面表面**；安装页使用**垂直步骤列表**。主操作仍只有一个，安装中只有一个取消入口。
- 首页与安装页只消费 application 快照；主按钮文字、enabled 与原因来自 `HomeSnapshot`，UI 不根据账号 / Java / 实例布尔值推导。
- 当前所有任务状态由 `src/app` 的 `DemoController` 驱动；真实微软登录、版本目录、Java 获取、下载、校验、安装与游戏启动尚未接入。

## 2. 约束引用与不可违反的边界

产品范围、目标平台、性能目标和里程碑以 [MVP 项目规划](../MVP项目规划.md) 为准；模块依赖、数据约定、任务状态与失败恢复以 [架构设计](../架构设计.md) 为准；构建与测试边界以 [构建与测试](../构建与测试.md) 为准。本文只写界面决定，不重复主规划中的平台与性能论证。

### 2.1 UI 只消费应用快照

| UI 可以做 | UI 不得做 |
| --- | --- |
| 展示 application 提供的只读快照 | 解析版本 JSON、资源列表或安装清单 |
| 把稳定枚举 / 错误码映射为中文文案 | 比较 Java 主版本、架构或判断版本兼容性 |
| 格式化已给出的字节、路径和版本标签 | 自行计算安装阶段、下载总量或可用空间 |
| 根据快照决定控件可见、可用和焦点 | 根据账号 / 实例 / Java 三个布尔值自行推导主操作 |
| 维护焦点、滚动、未保存草稿等界面局部状态 | 维护第二份“安装中”“已登录”业务状态 |
| 打开文件选择框并交给 application 校验 | 规范化路径、拼接数据目录或判断写权限 |
| 请求登录、安装、取消、重试、保存等命令 | 判断错误是否可重试、解析异常文本或读取凭据 |

原则：**快照没有提供的数据，显示“未知 / 待应用层提供”，不猜测。** 版本、Java、安装和路径规则属于 core / application；UI **不复制**版本 / Java / 安装规则，主按钮由 application 给出的 `PrimaryAction` 决定。

账号授权、安装就绪、游戏进程是三种独立状态。安装就绪不等于进入主菜单；游戏退出不得触发重新安装；取消、重试或切换实例后，按 `taskId` 忽略过期通知。

### 2.2 原生实现与资源

- 产品实现是 C++20 + Qt 6 Widgets；HTML 候选和对比页只用于设计评审，不进入产品，不引入 WebView、QML、JS 应用或本地 Web 服务。
- 使用 Windows 系统标题栏，不做无边框窗口；原生内容区没有仿造的第二条标题栏。窗口客户区按 1120 × 720 设计，实际外框由 Windows 绘制。
- 不使用大型皮肤库、持续动画、远程字体或远程图片；图片经 qrc 打包，只有一份共享 JPEG。
- 图标与叶形由项目绘制；华小科角色衍生设计不复制学校校徽，不声称官方背书。素材来源与授权边界单独记录；不挪用 PCL / HMCL 图标、主题或截图。
- 生产界面由 Qt 控件渲染；`resources/mockups/` 仅保留设计评审稿，不作为运行时整页皮肤。

## 3. 方向探索与推荐

### 3.1 三个方向

| 方向 | 首屏骨架 | 字体 / 色彩 | 主视觉与记忆点 | Qt 表达 | 主要风险 |
| --- | --- | --- | --- | --- | --- |
| **Campus Desk**（推荐） | 216 编号侧栏 + 一张 840 桌面；桌面内左为实例 / 状态 / 摘要，右为华小科插画 / 快捷入口；底部固定主操作 | 微软雅黑 UI；暖纸 `#F4F0E7`、桌面 `#FFFCF6`、深红 `#8C1D2F`、墨 `#23201C` | 华小科树荫插画与校园远景；编号目录；桌面底边的“开始”位置 | `QListWidget` + `QVBoxLayout` + `QFrame#Desk` + `QGridLayout` + `PrimaryActionBar` | 暖纸色容易落回“米色模板”，需靠单一桌面、编号和角色背景保持具体 |
| **Launch Deck** | 顶部导航 + 暗色启动带（实例名 + 主按钮 + 门廊）+ 三列状态轨；无侧栏 | Bahnschrift + 微软雅黑 UI；冷底 `#EFF3F4`、暗带 `#17282C`、红 `#B23A2E`、青 `#1F5C5A` | 三根红柱的门廊；暗带里的主按钮 | 顶部 `QToolBar` / `QHBoxLayout` + 暗色 `QFrame` + `QGridLayout` | 视觉更强，但导航位置改变、暗色面板增加实现与对比度成本 |
| **Field Guide** | 168 章节栏 + 856 纸面；纸面左为实例 / 状态 / 主按钮，右为线稿 / 摘要 | SimSun 标题 + 微软雅黑 UI 正文 + Georgia 数字；纸底 `#ECEDDF`、纸面 `#FCFCF2`、印章红 `#A33A2B` | 教学楼与梧桐线稿；H 方印；章节编号 | 窄 `QListWidget` / `QTabBar` + `QScrollArea` + 纸面 `QFrame` | 更像阅读页面，启动器任务感较弱；宋体回退与 200% 缩放风险高于 A |

设计调性共用：安静、精确、友好，不幼稚；能量偏安静，完成度偏精致，密度中等，分量中等，严肃度偏庄重。三个方向都保留一个主操作和清楚的安装状态，不堆装饰、动画或彩色徽章。

标杆说明：本轮阅读了项目内对 PCL / HMCL 的架构记录，但**没有抓取或复用两者的运行画面、图标或主题素材**，也没有把其界面当作复刻目标。方向判断来自本产品的受众、安装等待场景和校园主题；不声称做过 PCL / HMCL 的像素级拆解。

### 3.2 为什么选择 Campus Desk

1. **维护成本最低**：编号导航、桌面、状态行、固定主操作条都能用标准 Qt Widgets 表达；不需要暗色自绘面板、宋体标题或横向仪表布局的特殊约束。
2. **新手最易懂**：左侧固定导航 + 一个主操作 + 三行准备状态；不需要先理解顶部导航或章节结构。
3. **资源可控**：纯色、细线和一张共享静态 JPEG（约 604 KiB）；复用同图裁切，不引入远程资源或持续动画。原生演示已验证一次解码缓存，未做完整内存基准。
4. **校园识别明确**：暖纸、深红、编号目录、华小科与树荫远景形成同一语言；参考图不直接搬入产品，角色权利单独记录。
5. **能延续到安装页**：同一张桌面可以变成“垂直步骤 + 本次安装 + 底部取消条”，状态语义不需要另造组件。
6. **已经落地**：本轮按此方向实现了原生页面、侧栏、操作条、共享 JPEG 与安装状态，没有停在静态稿。

Launch Deck 的启动带更有冲击力，适合后续可选视觉方向；Field Guide 的手册感更强，但更像阅读产品。两者不删除，保留在对比页。

## 4. 全局框架

### 4.1 窗口骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ Windows 系统标题栏（最小化 / 最大化 / 关闭由系统绘制）          │
├──────────────┬───────────────────────────────────────────────┤
│ 编号侧栏 216 │ 页面标题 / 一句说明（固定）                     │
│ 01 首页      ├───────────────────────────────────────────────┤
│ 02 安装游戏  │ 内容（QScrollArea，可纵向滚动）                 │
│ 03 设置      │                                               │
│ 04 日志      ├───────────────────────────────────────────────┤
│              │ 固定主操作条（安装页为取消入口）                 │
└──────────────┴───────────────────────────────────────────────┘
```

结构：`QMainWindow`（Windows 原生标题栏）→ 中央 `QWidget` → `QHBoxLayout`（216 侧栏 + 右侧 `QStackedWidget`）。页面由 `PageScaffold` 组成：页面标题、`QFrame#Desk`（内部上方 `QScrollArea`、下方固定 `PrimaryActionBar`）。内容滚动时操作条保持可见；四页共用同一骨架。

导航用 `QListWidget`（单选、46 行高、编号 + 文本）；选择它而不是自绘按钮，是为了方向键、焦点和可访问性语义。编号是文案的一部分，不用通用图标库。设置与日志导航项禁用，并显示后续批次说明。

### 4.2 尺寸与响应式

- 设计客户区：1120 × 720 逻辑像素；最终 SVG 使用同一画布。Windows 外框与标题栏不计入客户区。
- 实现默认窗口：1120 × 720 逻辑像素；启动时钳制到当前屏幕可用工作区并预留边距；最小 840 × 460。
- 页面断点：页面可用宽度 < 820 时，首页 / 安装页的左右列改为纵向；此时桌面内容在 `QScrollArea` 内滚动，固定操作条仍可见。窗口宽度 < 960 时侧栏 200，高度 < 680 时隐藏插画装饰。
- 判断依据是窗口逻辑宽度，不是物理分辨率；100% / 150% / 200% 与窄工作区都使用同一套布局规则。
- 页面标题和主操作条固定在滚动区外；200% 缩放下主操作仍可见。
- 侧栏在 ≥ 960 时宽 216，< 960 时宽 200；导航文字不截断。
- 长路径用 `QFontMetrics::elidedText` 中间省略，并在只读输入框 / tooltip 中保留完整值；不改写中文、空格或反斜杠。

## 5. 页面规格

### 5.1 首页（Campus Desk）

**目标**：新手打开后 5 秒内知道“我是谁、当前实例是什么、是否准备好、下一步做什么”。每屏只有一个主操作。

**信息层次**

1. 问候与当前实例：`下午好，林知远`、`校园生存 · Minecraft 1.21.4`；右侧是样例时间。
2. 准备状态：账号、Java 运行时、游戏实例三行；每行有勾选圆点、名称、值、状态。状态来自快照，不由 UI 判断。

4. 小提示：设置入口、日志与错误入口；不堆额外卡片。
5. 固定主操作条：`准备就绪` + `启动游戏`；次操作只保留“安装其他版本”。
6. 演示标记：侧栏“界面演示 · 样例数据”、窗口标题“HustMCL 界面演示”和侧栏“登录、下载与启动尚未接入”。

| 区域 | 组件 | 说明 |
| --- | --- | --- |
| 侧栏 | `Sidebar` + `QListWidget` | 01–04 编号 + 文本；当前行红底、左侧红条；设置 / 日志禁用 |
| 问候 | `PageHeader` 的 `QLabel#PageTitle` | 30 px / 22.5 pt；问候文字来自 `HomeSnapshot.greeting` |

**状态**

- 未登录：问候改为“登录后开始”，状态行显示“等待登录”，主按钮“登录”。
- 无实例：状态行显示实例缺失，主按钮“安装游戏”；不伪造实例。

### 5.2 安装游戏

**目标**：让用户确认“装哪个版本、装到哪里、现在到哪一步、如何安全取消”，同时不伪造进度。

**信息层次**

1. 页面标题与阶段：`安装游戏`、`为校园生存准备 Minecraft 1.21.4`、`阶段 4 / 6`。
2. 左列垂直步骤：未安装 → 解析版本 → 准备环境 → 下载文件 → 校验文件 → 就绪；完成 / 当前 / 未来三种状态。当前下载行展开“总量未知 · 已传输 128.4 MB”。
3. 右列：版本 1.21.4（推荐 / 已验证）、目录、空间、取消与恢复、完成后的边界。
4. 固定底栏：`安装进行中` + `下载文件 · 总量未知 · 已传输 128.4 MB` + **唯一**的“取消安装”。
5. 演示标记：侧栏“界面演示 · 样例数据”和“登录、下载与启动尚未接入”。

**阶段与进度**

- 阶段名由 application 枚举映射；UI 不用文件数量或耗时猜阶段。
- `totalBytes` 有值：可以显示确定进度、已传输 / 总量、百分比；`copy::progressFraction()` 先把完成 / 总量限制在 `[0, 1]`，再换算到百分比和 0–1000 进度条；极大完成量饱和到 100%，负完成量归零。
- `totalBytes` 为空或非正：只显示阶段、已传输量、当前子阶段；**不显示百分比、不显示假进度条、不使用循环动画**。
- 快照尚未到达时不显示“0%”或空进度条，显示“正在获取任务状态…”。

**取消与提交**

- 下载 / 校验 / 准备阶段且 `cancellable == true`：显示“取消安装”；点击后立即禁用并改为“正在取消…”，等待快照进入 `Cancelled`，不能先显示“已取消”。
- `Cancelling`：按钮禁用，文案“正在取消…”，不重复发送取消。
- `Committing` 或 `cancellable == false`：取消按钮禁用，旁注“正在完成安装，无法取消”；提交窗口不可取消。
- `Failed`：隐藏取消，当前步骤按阶段显示“准备环境失败 / 下载失败 / 校验失败 / 提交失败”等，按 `TaskError.retryable` 显示重试或只给日志；`Succeeded` 只代表安装就绪，启动状态另管。
- 取消和失败保留已校验文件；重试创建新任务并从检查缓存开始，由 application 决定，UI 不承诺断点续传。

**Qt Widgets 分工**

| 区域 | 组件 | 说明 |
| --- | --- | --- |
| 垂直步骤 | `StageList` + `StageRow` | 标准 `QVBoxLayout` 组合；圆点 / 标题 / 子状态；当前行展开字节数 |
| 未知总量 | `UnknownProgressNote` | 虚线边框 + “总量未知” + 已传输量；无动画 |
| 版本 | `QLabel#VersionLabel` + 两个徽章 | 本轮只读展示版本与推荐 / 已验证；版本选择留给安装前流程 |
| 目录 | `ElidedLabel#InstallPath` | 中间省略 + tooltip / 可访问名保留完整中文路径；安装中不可更改 |
| 空间 | `SummaryRow` | 需要 / 可用；未知值显示“未知”，不估算 |
| 取消 / 重试 | `PrimaryActionBar` 的 `CancelAction` / `PrimaryAction` | 取消白底红边；重试深红主按钮；唯一操作入口在固定底栏 |
| 说明 | `QLabel` | 取消 / 恢复 / 完成后边界；不堆重复提示 |

**键盘**：窗口显示后初始焦点在可用的“取消安装”或“重试 / 继续安装”；Tab 到侧栏与其他链接；安装中不自动把焦点移到取消，避免误触；Esc 不直接取消安装。

**预览**：[install.svg](../../resources/mockups/install.svg)。

**目标**：先告诉用户“发生了什么、我能做什么”，再提供可导出的脱敏日志；不把原始堆栈和凭据放在首屏。

**信息层次**

1. 错误摘要：用户能理解的原因、影响范围、下一步。

### 6.1 主按钮

主按钮文案只由 `HomeSnapshot.primaryAction` 映射；`HomeSnapshot` 同时提供 `primaryEnabled` 与 `primaryReason`。UI 不根据账号 / 实例 / Java 三个布尔值自行推导；本批 `hustmcl_ui_tests` 对此有回归。

| `primaryAction`（建议） | 文案 | 触发 | 显示条件 |
| --- | --- | --- | --- |
| `SignIn` | 登录 | 启动微软账号流程 | 未登录 |
| `Install` | 安装游戏 | 进入安装页 / 开始安装 | 已登录、无就绪实例 |
| `PrepareEnvironment` | 准备环境 | 获取或选择 Java 运行时 | 实例需要环境、Java 未就绪 |
| `Launch` | 启动游戏 | 调用启动用例 | 账号、实例、环境全部就绪 |
| `Retry` | 重试 | 重试当前可恢复任务 | `TaskError.retryable == true` |
| `None` | 不显示主按钮 | — | 没有安全可执行动作；显示日志入口，不编造操作 |

忙碌与终态：

| 场景 | 主按钮 | 次操作 | 说明 |
| --- | --- | --- | --- |
| 登录中 | “正在登录…”禁用 | 取消登录（若应用支持） | 不显示旧账号为已登录 |
| 安装中 | “安装中…”禁用 | 安装页“取消安装” | 主按钮不重复触发任务 |
| 准备环境中 | “准备环境中…”禁用 | 取消（若可取消） | 显示阶段，不显示虚构百分比 |
| 启动中 | “启动中…”禁用 | 查看日志 | 启动不是安装 |
| 游戏运行中 | “游戏运行中”禁用 | 查看日志 | MVP 不提供结束游戏 |
| 取消请求中 | “正在取消…”禁用 | 无 | 快照确认后才显示“已取消” |
| 已取消 | “继续安装” | 查看日志 | 复用缓存，由 application 决定 |
| 错误且可重试 | “重试” | 查看日志 | 不自动无限重试 |
| 错误且不可重试 | 无主按钮 | 查看日志 / 更改目录 | 给出具体下一步 |

### 6.2 取消状态

| 任务状态 / 阶段（快照） | 取消按钮 | 文案 | 规则 |
| --- | --- | --- | --- |
| `TaskState::Running` 且 `cancelAvailable` | 可用 | 取消安装 | 点击后进入 `Cancelling`，按钮立即禁用 |
| `TaskState::Cancelling` | 禁用 | 正在取消… | 不重复发送；等待退出和清理 |
| `TaskPhase::Committing` 或 `cancelAvailable == false` | 禁用 | 取消不可用 | 旁注“正在完成安装” |
| `TaskState::Succeeded` | 隐藏 | — | 只代表安装就绪 |
| `TaskState::Failed` | 隐藏 | — | 按 `TaskError.retryable` 显示重试或日志 |
| `TaskState::Cancelled` | 隐藏 | — | 显示“继续安装”，重新规划并检查缓存 |

取消安装不做二次确认弹窗：它是可恢复操作。但取消按钮不能与主按钮相邻到容易误触，且点击后必须显示“正在取消…”，不能先显示“已取消”。

### 6.3 错误展示

当前最小契约使用 `TaskError`（`TaskErrorCode`、`summary`、`detail`、`retryable`）和 `TaskSnapshot`。完整 `AppError` 与真实后端错误分类仍待 application 用例；UI 只使用安全摘要、稳定错误码和 `retryable`，不解析原始异常文本。

| 错误类别（建议） | 展示位置 | 首屏重点 | 可用动作 |
| --- | --- | --- | --- |
| `Auth.*` | 首页账号区 / 日志 | 登录过期或授权失败 | 重新登录；不显示 token |
| `Network.*` | 安装 / 日志 | 网络中断或超时；已下载内容保留 | 可重试时“重试” |
| `Disk.*` | 安装 / 设置 | 空间不足或路径不可用 | 更改目录、释放空间；不自动重试 |
| `Permission.*` | 安装 / 设置 | 目录无写权限；给出具体路径 | 更改目录 |
| `Metadata.*` | 安装版本区 | 版本信息无效或不完整 | 刷新列表；不猜兼容性 |
| `Integrity.*` | 安装 / 日志 | 校验未通过；可复用部分保留 | 从缓存重试；不承诺断点续传 |
| `Launch.*` | 首页 / 日志 | 游戏未能启动 | 重试启动（若允许）、导出日志 |
| `Unknown` | 日志 | 通用说明 + 错误码 + 任务 ID | 导出日志；不显示原始异常全文 |

错误详情允许出现：错误码、阶段、`taskId`、脱敏路径、版本标签。禁止出现：访问令牌、认证 URL 中的凭据、完整启动命令行、未脱敏隐私路径。

## 7. 键盘与 100 / 150 / 200% 缩放验收

本节是 Qt 原生演示的验收基线。本轮已实际运行 Windows QPA，并生成离屏 1x / 1.5x / 2x 与 900×500 窄窗口截图；未做完整的逐控件 Tab 走查、屏幕阅读器、Windows 高对比度或 200% 物理工作区多显示器验收。

### 7.1 键盘

- 所有交互控件可仅用键盘到达和操作；Tab / Shift+Tab 顺序与视觉顺序一致；无焦点陷阱。
- 焦点环 2 px、对比度 ≥ 3:1；任何控件获得焦点都可见；不依赖悬停。
- Enter / Space 激活按钮；方向键在导航、单选组、下拉框移动；Esc 只关闭弹层 / 对话框，不取消安装、不退出账号、不丢弃设置。
- 页面切换后焦点落在新页面第一个有意义的控件。
- 长中文路径可通过只读输入框选择复制，或 tooltip 查看完整值。
- 错误出现时通过可访问性事件播报摘要，不强行抢焦点。

| 页面 | 初始焦点 | 关键路径 | 禁止 |
| --- | --- | --- | --- |
| 首页 | 可用主按钮 | Tab → 设置 / 日志 → 主按钮 | 无确认时退出账号 |
| 安装 | 可用的取消 / 重试 | Tab 到目录 / 说明 → 操作条 | 安装中不自动聚焦取消；Esc 不取消 |
| 设置 | Java 模式 | 字段顺序 → 保存；`Ctrl+S` | Esc 不静默丢弃修改 |
| 日志 | 日志视图 | PageUp / PageDown / Ctrl+C → Tab 到导出 | 自动滚动不打断向上阅读 |

### 7.2 缩放

验收机：Windows 10 / 11 x64，1920 × 1080，100% / 150% / 200%；记录 Qt 版本、显卡、窗口实际逻辑 / 物理尺寸。

| 缩放 | 本轮实际证据 | 布局结果 | 仍需人工/自动补充 |
| --- | --- | --- | --- |
| 100% | 离屏 1120 × 720 | 双列桌面、固定操作条；无文字裁切 | 真实 100% Windows 显示器 |
| 150% | 离屏 1680 × 1080；Windows 150% 客户区 1680 × 1080 | 双列桌面；文字与图片清晰 | 150% 下实际窗口钳制行为 |
| 200% | 离屏 2240 × 1440；900 × 500 窄窗口重排 | 窄窗口改为纵向，操作条固定，内容滚动 | 200% 物理工作区、多显示器 |
| 窄窗口 | 900 × 500（隐藏侧栏插画） | 首页 / 安装列纵向；无横向滚动 | 键盘逐项走查 |

实现要求：不关闭 Qt 高 DPI 缩放；使用逻辑像素、`QFontMetrics` 省略和 `sizeHint`，不写死物理像素；图标用 QPainter；固定操作条在窄窗口仍可见。上述离屏截图不等于 200% Windows 物理验收。`--scale` 是 Qt 缩放提示，不是绝对 DPI；本机 Windows 原生系统为 150%，所以 `--scale 1` 也不应期待原生 1120×720/DPR 1.0。

### 7.3 构建进展与边界

Qt 6.10.3 的 MinGW 13.1 Widgets / Test 已用于实际构建、CTest、Windows QPA 运行和截图；`hustmcl_desktop.exe` 使用 Windows GUI 子系统（`qt_add_executable(... WIN32 ...)`），双击不会多一个控制台。截图 CLI 需通过 `Start-Process -Wait` 或 `cmd /c` 调用；这样 stdout/stderr 重定向和非零退出码仍有效，PowerShell 的 `&` 对 GUI 子系统不会等待。MSVC 安装仍受微软清单 TLS 连接失败阻碍；`windeployqt`、干净 PATH 与干净 Windows 10/11 验收尚未完成。

## 8. 当前最小 application 契约

**现状**：本轮已新增 `src/application` 与 `hustmcl_application`，提供两个页面所需的最小值类型快照和 `FrontendGateway`。它们是演示契约，不是完整生产接口；真实认证、目录、下载和设置仍待后续用例接入。UI 已按这些类型实现并通过 Qt Test。

### 8.1 只读快照

| 类型 | 当前字段 | 用途 / 约束 |
| --- | --- | --- |
| `HomeSnapshot` | `greeting`、`timeLabel`、`account`、`instance`、`environment`、`primaryAction`、`primaryEnabled`、`primaryReason`、`launch` | 首页一次渲染；主操作由 application 给出 |
| `AccountSnapshot` | `state`（未登录 / 登录中 / 已登录 / 已过期 / 错误）、`displayName`、`providerLabel` | 不含 token |
| `InstanceSnapshot` | `instanceId`、`displayName`、`versionLabel`、`editionLabel`、`state` | 版本标签是展示值 |
| `EnvironmentSnapshot` | `state`（缺失 / 检测中 / 就绪 / 无效）、`versionLabel`、`architectureLabel`、`sourceLabel` | 兼容判断在 core / application |
| `LaunchSummary` | `memoryMb`、`closeLauncherAfterLaunch` | 首页摘要 |
| `TaskSnapshot` | `taskId`、`instanceId`、`phase`、`state`、`completedBytes`、`totalBytes`（`std::optional`）、`cancelAvailable`、`cancelReason`、`retryAvailable`、`retryReason`、`error`（`std::optional<TaskError>`）、`phaseDetail` | `totalBytes` 为空表示未知，UI 不猜 |
| `TaskError` | `code`、`summary`、`detail`、`retryable` | UI 用 `code` 映射文案；不解析原始异常文本 |
| `InstallSnapshot` | `task`、`instanceDisplayName`、`versionLabel`、`variantLabel`、`recommended`、`verified`、`targetPath`、`requiredBytes`、`freeBytes` | 目录与空间值由 application 提供；未知为 `std::optional` 空 |
| 后续类型 | `VersionCatalogSnapshot`、`InstallTargetSnapshot`、`SettingsSnapshot`、`LogSnapshot` | 设置、日志、版本选择与真实安装用例尚未实现 |

补充：每次任务通知带 `taskId`；UI 在取消、重试、切换实例后忽略旧 ID；`TaskSnapshot` 不持久化运行中状态作为恢复依据；未知枚举显示“状态未知”+ 代码，不当作成功；凭据、token、完整认证 URL 不进入 UI。

### 8.2 命令 / 用例

| 目的 | 当前方法 | 说明 |
| --- | --- | --- |
| 首页主操作 | `requestPrimaryAction()` | 演示中不伪造登录 / 安装 / 启动，窗口给出“尚未接入”反馈 |
| 取消任务 | `requestCancel(taskId)` | 演示控制器先进入 `Cancelling`，计时器确认后进入 `Cancelled` |
| 重试 / 继续安装 | `requestRetry(taskId)` | 生成新 `taskId`，重置为运行中的下载阶段 |
| 后续真实命令 | `signIn()`、`startInstall()`、`startLaunch()`、`loadSettings()`、`saveSettings()`、`exportLogs()` 等 | 仍未实现；需真实 application 用例 |

信号：`homeChanged(const HomeSnapshot&)`、`installChanged(const InstallSnapshot&)`。全部在 UI 线程同步发出；真实后端接入后应排队到 UI 线程。

### 8.3 契约要求

- application 是任务状态唯一写入者；UI 只读快照，不维护第二份“安装中”布尔值。
- 取消 / 重试 / 切换实例后旧 `taskId` 的通知必须可忽略；不能靠最后一条通知猜当前任务。
- 取消请求只进入 `Cancelling`；`Cancelled` 必须在工作线程退出和清理后发出。
- `TaskError.retryable` 由 application 决定；网络瞬态错误有上限退避，磁盘不足 / 无权限 / 无授权不可无限重试。
- 登录过期、登出后旧回调不得重新保存凭据；UI 不接触凭据。
- 安装与游戏运行状态分开；游戏退出不得触发重新安装。
- 快照不携带凭据；错误、日志、导出内容统一脱敏。
- UI 文案由 UI 侧统一维护（错误码 → 中文、阶段 → 中文）；application 不返回最终用户长句。

### 8.4 后续 application 工作

1. 用真实微软认证、版本目录、Java 获取和下载 / 校验用例替换 `DemoController`，保持相同快照边界。
2. 明确 `TaskSnapshot` 的持久化 / 重启恢复语义；当前演示不持久化。
3. 版本目录接口：推荐版本、`verified` 语义、Java 要求展示值；本轮安装页只读。
4. 安装目标校验接口：路径规范化、权限、空间、所需字节。
5. 设置草稿 / 校验 / 保存接口，以及 Java 探测状态枚举。
6. 日志读取、脱敏导出、打开日志目录接口。
7. 真实 MSVC / Qt 构建、部署与干净系统验收。
