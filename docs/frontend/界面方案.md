## 1. 不可违反的边界

### 1.1 UI 只消费应用快照

UI 是 application 状态的展示与命令入口，不是第二套业务规则实现。

| UI 可以做 | UI 不得做 |
| --- | --- |
| 展示 application 提供的只读快照 | 解析版本 JSON、资源列表或安装清单 |
| 把稳定枚举 / 错误码映射为中文文案 | 比较 Java 主版本、架构或判断版本兼容性 |
| 格式化已给出的字节数、路径和版本标签 | 自行计算安装阶段、下载总量或可用空间 |
| 根据快照决定控件的可见、可用与焦点 | 根据账号 / 实例 / Java 三个布尔值自行推导主操作 |
| 维护焦点、滚动位置、未保存草稿等界面局部状态 | 维护第二份“安装中”“已登录”业务状态 |
| 打开文件选择框并把用户选择交给 application 校验 | 自行规范化路径、拼接数据目录或判断写权限 |
| 请求重试、取消、登录、保存等命令 | 判断错误是否可重试、解析异常文本或读取凭据 |

原则：**快照没有提供的数据，界面显示“未知 / 待应用层提供”，不猜测。** 如果某个判断需要版本、Java、安装或路径规则，它属于 core / application，应在快照或命令结果中给出。

应用层是任务状态的唯一写入入口。页面切换、窗口缩放、焦点变化不会改变业务状态；取消、重试和切换实例后，UI 必须按 `taskId` 忽略过期通知。

### 1.2 三类状态分开

账号授权、安装就绪、游戏进程是三种独立状态，首页不能用同一个布尔值概括。安装成功只表示“就绪”，不表示游戏已进入主菜单；游戏退出也不得触发重新安装。UI 只展示 application 给出的组合结果与主操作建议。

### 1.3 视觉与资源约束

- 使用 Qt Widgets 标准布局与少量 QSS，不引入大型皮肤库、QML、WebView 或前端框架。
- 默认使用 Windows 系统标题栏；不制作无边框窗口，不接管最小化 / 最大化 / 关闭。
- 不使用装饰性持续动画、轮询刷新或远程资源。任务进行中只随快照更新阶段和字节数。
- 图标与插画使用原创几何图形，不冒用学校校徽、学校视觉识别素材，也不挪用 PCL / HMCL 的图标、主题或截图。
- 本批两张 SVG 是评审稿，不是运行时皮肤；页面文字、账号和实例都是静态样例，上线界面由真实控件渲染。
- 所有示例账号、实例、版本、路径、空间和传输量都必须醒目标注“设计示例”。

## 2. 全局框架

### 2.1 窗口骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ Windows 系统标题栏（最小化 / 最大化 / 关闭由系统绘制）          │
├──────────────┬───────────────────────────────────────────────┤
│ 侧栏 232 px  │ 页面标题 + 一句说明（固定，不随内容滚动）        │
│              ├───────────────────────────────────────────────┤
│ 首页         │ 页面内容（QScrollArea，可纵向滚动）             │
│ 安装游戏     │                                               │
│ 设置         │                                               │
│ 日志与错误   ├───────────────────────────────────────────────┤
│              │ 主操作栏（固定，不随内容滚动）                   │
└──────────────┴───────────────────────────────────────────────┘
```

结构：`QMainWindow` → 中央 `QWidget` → `QHBoxLayout`（左侧导航 + 右侧页面容器）。右侧页面容器为 `QVBoxLayout`：页面标题、`QScrollArea`、固定主操作栏。四个页面都使用同一个 `PageScaffold`，避免每页各写一套边距和滚动逻辑。

导航使用 `QListWidget`（单选、固定行高、图标 + 文本），当前行与 `QStackedWidget` 同步。选择它而不是一组自绘按钮，是为了直接获得方向键导航、焦点和可访问性语义。导航项：首页、安装游戏、设置、日志与错误。

### 2.2 尺寸与响应式规则

- 设计画布与 SVG 预览：1120 × 720 逻辑像素（100% 缩放下的视觉基准）。
- 实现默认窗口：1120 × 720 逻辑像素；启动时钳制到当前屏幕可用工作区并预留边距，不超出屏幕。
- 最小窗口：840 × 460 逻辑像素。低于该尺寸不保证可用，应阻止继续缩小。
- 响应式断点：窗口宽度 ≥ 1120 时使用双列卡片；< 1120 时改为单列纵向排列。判断依据是窗口宽度，不是物理分辨率。
- 页面标题和主操作栏固定在滚动区外；内容再长也只滚动中间区域，保证取消 / 保存 / 启动入口始终可达。
- 侧栏在 ≥ 960 时宽 232，< 960 时宽 200；导航文字不截断，不使用图标-only 模式。
- 文本超长时使用 `QFontMetrics::elidedText` 中间省略，并在 tooltip 或可选择的只读输入框中提供完整值。中文路径、空格和反斜杠不得被 UI 改写。

### 2.3 四页共用基础组件

| 组件 | Qt 基础 | 职责 | 使用页面 |
| --- | --- | --- | --- |
| `PageScaffold` | `QWidget` + `QVBoxLayout` | 标题、说明、滚动区、固定底栏的统一骨架 | 全部 |
| `SectionCard` | `QFrame#Card` + `QVBoxLayout` | 白色卡片、圆角、1 px 边框、统一内边距 | 全部 |
| `PageHeader` | `QLabel` × 2 | 页面标题与一句说明；不承载业务状态 | 全部 |
| `StatusPill` | `QLabel` + 动态属性 | 状态文字 + 图标 / 圆点，颜色不是唯一信息 | 首页、安装、设置、日志 |
| `InlineNotice` | `QFrame` + 图标 + 标题 + 正文 + 动作 | 错误、警告、成功提示；错误码放在详情区 | 全部 |
| `PrimaryActionBar` | `QFrame` + `QLabel` + `QPushButton` | 固定底部主操作；按钮文字由 `PrimaryAction` 映射 | 首页、安装、设置 |
| `FieldRow` | `QLabel` + 控件 + 说明 / 错误 | 设置项的统一标签、帮助文字和校验位置 | 设置、安装目录 |
| `StageRail` | `QWidget` + `QHBoxLayout` 组合 | 安装阶段：未安装 → 解析 → 环境准备 → 下载 → 校验 → 就绪 | 安装 |
| `UnknownProgress` | `QFrame` + 虚线边框 + 文本 | 总量未知时的静态占位；不自绘循环动画 | 安装 |
| `LogView` | `QPlainTextEdit`（只读） | 脱敏日志、选择复制、滚到底部才自动跟随 | 日志 |
| `EmptyState` | `QWidget` + 图标 + 文案 | 无实例、无日志、无错误时的解释与下一步 | 首页、日志 |
| `VersionRow` | `QRadioButton` + 标签 + 徽章 | 版本选择行；推荐 / 已验证标记来自快照 | 安装 |

组件只负责显示和发出信号，不读取文件、不访问网络、不计算业务规则。后续 `src/ui` 首批实现时应先落这些组件，再拼页面。

| `primary.hover` | `#A02439` | 主按钮悬停 | — |

颜色使用规则：

- 深红只用于主操作、当前阶段和品牌线条，不大面积铺满页面，避免把取消或危险操作也染成主色。
- 取消安装使用白底 + 深红文字 + 柔和红边框，不使用红色实心按钮，降低误触。
- 成功 / 警告 / 错误必须同时有文字或图标，不能只靠颜色区分。
- 所有正文文字与背景的组合目标 ≥ 4.5:1，大字与图形目标 ≥ 3:1。上表是设计目标，最终以 Qt 实际渲染和取色检查为准。

### 2.6 字体与字号

字体族：`Microsoft YaHei UI` → `Microsoft YaHei` → `Segoe UI` → `sans-serif`。不打包字体文件，不引用远程字体；缺少前两项时由系统回退。

| 角色 | 设计 px（100%） | Qt 实现建议 | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- | --- |
| 辅助 / 徽章 | 11–12 | 8.5–9 pt | 400 | 1.4 | 说明、时间、路径辅助 |
| 正文 | 14 | 10.5 pt | 400 | 1.6 | 普通文本、表单值 |
| 次级标题 | 16 | 12 pt | 600 | 1.4 | 卡片标题 |
| 页面标题 | 20 | 15 pt | 600 | 1.3 | 四个页面标题 |
| 首页问候 / 主数值 | 26 | 20 pt | 600 | 1.25 | 首页问候 |

字号规则：

- Qt 控件优先使用 pt，跟随 Windows 文本缩放；QSS 中使用对应 pt 值。SVG 预览使用 px 仅用于 100% 画布。
- 不通过放大字号补偿布局，不使用小于 11 px 的正文。
- 中文正文每行控制在约 36–48 个汉字；长说明拆成短句，不用整段小字。
- 数字（字节、百分比、内存）使用与正文相同的字体，不做艺术化字形，保证可读。

### 2.7 控件状态

| 控件 | 默认 | 悬停 | 按下 | 焦点 | 禁用 |
| --- | --- | --- | --- | --- | --- |
| 主按钮 | 深红底白字 | 提亮为 `primary.hover` | 压暗为 `primary.pressed` | 外扩 2 px `focus` 环 | `disabled.bg` / `disabled.text`，无悬停 |
| 次级按钮 | 白底、`border.default` 边框、深色字 | 边框 `border.strong`，浅灰底 | 浅灰底加深 | 2 px `focus` 环 | 降低对比，不响应 |
| 取消安装 | 白底、柔和红边框、深红字 | 浅红底 | 浅红底加深 | 2 px `focus` 环 | 状态不可取消时禁用并给出原因 |
| 导航项 | 透明、深色字 | 浅灰底 | 浅灰底 | 2 px `focus` 环 | 无（始终可切换） |
| 单选项 / 复选项 | 深红选中标记 | 浅红底 | 正常 | 2 px `focus` 环 | 灰色文字 + 不可切换 |

QSS 的焦点边框要预留空间或使用外扩绘制，避免获得焦点时控件跳动。若 QSS 无法稳定绘制焦点环，使用共享的 `QProxyStyle` 或轻量自绘，不在每个页面重复实现。

## 3. 页面规格

### 3.1 首页

**目标**：新手打开后 5 秒内知道“我现在是谁、要做什么、能不能开始”。每屏只有一个主操作。

**信息层次（从上到下）**

1. 页面标题与账号状态：当前账号、登录 / 过期 / 未登录。
2. 主视觉问候与当前实例：实例名、版本标签、三个准备状态（账号、Java、实例）。
3. 准备状态明细：每一项的值、来源和是否就绪；值来自快照，不由 UI 判断。
4. 启动摘要：内存上限、启动后启动器行为；提供设置入口。
5. 固定主操作栏：一句原因 / 结果说明 + 一个主按钮；次操作只保留“安装其他版本”“设置”“日志与错误”等低权重入口。
6. 页脚：设计示例说明、版本与系统标题栏说明。

**布局**：左侧 232 侧栏；右侧内容 824 宽（1120 画布）。顶部为账号胶囊；中部 824 × 184 的主视觉卡片，右侧原创校园几何插画；其下左 520 准备状态卡、右 284 启动摘要卡；底部 824 × 100 主操作栏。

**Qt Widgets 分工**

| 区域 | 组件 | 说明 |
| --- | --- | --- |
| 页面骨架 | `PageScaffold` | 标题、滚动区、固定底栏 |
| 问候 | `QLabel#Greeting` | 26 px / 20 pt；账号名来自快照 |
| 实例 | `QLabel#InstanceLine` | 实例名 + 版本标签 + “设计示例” / 真实数据标识 |
| 准备状态 | 三个 `StatusPill` | 账号、Java、实例；就绪态用图标 + 文字 |
| 主视觉 | `QWidget#CampusIllustration` | 静态插画；优先用 `QSvgWidget`（需确认 QtSvg 可用），否则用 `QPainter` 绘制；不加载整页 SVG |
| 准备明细 | `SectionCard` + `QGridLayout` | 每行：名称、值、状态；不把值当按钮 |
| 启动摘要 | `SectionCard` | 内存、启动后行为；链接到设置 |
| 主操作 | `PrimaryActionBar` + `QPushButton#PrimaryAction` | 文案由 `PrimaryAction` 映射；禁用时旁注原因 |
| 次入口 | `QPushButton`（扁平） | 安装其他版本、设置、日志与错误 |

**空状态**

- 未登录：主视觉问候改为“登录后开始”，准备状态卡显示“等待登录”，主按钮“登录”，不显示虚假实例。
- 无实例：显示“还没有安装游戏”，主按钮“安装游戏”；Java 状态仍可显示，但不把“准备环境”当主操作。
- 无 Java：主按钮“准备环境”；说明会获取或选择运行时，不展示未确认的下载地址。
- 游戏运行中：主按钮“游戏运行中”禁用；可查看日志；不在 MVP 增加“结束游戏”。

**键盘**

初始焦点放在主操作按钮（若存在且可用）；Tab 依次经过账号入口（若有）、准备明细中的可操作项、启动摘要的“打开设置”、主按钮、次入口。Enter / Space 激活当前控件；Esc 不执行任何破坏性动作。

**预览**：[home.svg](../../resources/mockups/home.svg)。

### 3.2 安装游戏

**目标**：让用户确认“装哪个版本、装到哪里、现在到哪一步、如何安全取消”，同时不伪造进度。

**信息层次**

1. 顶部安装状态：当前阶段（第 n / 6 阶段）、阶段名、是否可取消；总量未知时明确写“总量未知”。
2. 版本：推荐版本置顶，带“推荐”“已验证”徽章；“其他正式版”在后。兼容性、Java 要求和“已验证”均由 application / core 提供，UI 不自行判断。
3. 目录与空间：安装目录、预计需要空间、可用空间；未知值显示“待应用层计算 / 未知”。
4. 安装说明：取消后的保留策略、失败重试从缓存开始、安装就绪不等于进入主菜单。
5. 取消入口：只保留一个，位于安装状态卡；不使用弹窗二次确认（取消可恢复，且弹窗会增加新手负担）。
6. 固定主操作栏：未开始时“开始安装”；安装中显示“安装中…”并禁用；失败时按 `AppError.retryable` 显示“重试”或只给“查看日志”。

**阶段轨**：未安装 → 解析 → 环境准备 → 下载 → 校验 → 就绪。阶段名由 application 枚举映射；UI 不用文件数量或耗时猜阶段。取消完成前显示“正在取消…”，不能提前显示“已取消”。

**进度展示规则**

- `totalBytes` 有值：显示确定进度、已传输 / 总量、百分比；百分比由已完成 / 总量得出，不额外估算。
- `totalBytes` 为空：显示静态虚线框 + “总量未知” + 已传输字节 + 当前子阶段；**不显示百分比、不显示假进度条、不使用循环动画**。
- 子阶段由 application 提供稳定的阶段代码，UI 映射为中文；不把服务端原始错误文本直接展示为进度。
- 快照尚未到达时不显示“0%”或空进度条，显示“正在获取任务状态…”。

**Qt Widgets 分工**

| 区域 | 组件 | 说明 |
| --- | --- | --- |
| 安装状态 | `SectionCard` + `QLabel` | 阶段标题、阶段序号、子阶段 |
| 阶段轨 | `StageRail` | 6 个节点 + 连接线；当前节点用深红，完成节点用深红实心，未来节点灰色 |
| 未知进度 | `UnknownProgress` | 虚线边框 + 文本，无动画 |
| 已知进度 | `QProgressBar` | 只在 `totalBytes` 有值时显示；设置范围为 0–总量 |
| 取消 | `QPushButton#CancelInstall` | 白底红边；`cancellable == false` 时禁用并 tooltip 原因 |
| 版本 | `SectionCard` + `QButtonGroup` + `VersionRow` | 单选；推荐 / 已验证徽章来自快照；安装中锁定 |
| 目录 | `FieldRow` + 只读 `QLineEdit` + `QPushButton` | 用户可选中复制完整路径；更改目录打开 `QFileDialog`，由 application 校验 |
| 空间 | `QLabel` | 需要 / 可用；未知值明确写“未知”，不估算 |
| 说明 | `SectionCard` | 取消、重试、完成后的边界说明 |

**取消与失败**

- 点击“取消安装”后按钮立即禁用并改为“正在取消…”，页面提示“正在停止任务并清理临时状态”；只有快照进入 `Cancelled` 才显示“已取消”。
- 提交窗口不可取消：`cancellable == false` 时按钮禁用，说明“正在完成安装，无法取消”。
- 取消和失败都保留已校验文件；重试创建新任务并从检查缓存开始，由 application 决定，UI 不承诺“断点续传”。
- 错误只显示用户能理解的原因和下一步；错误码、任务 ID 放在详情 / 日志入口，不把原始异常、URL 或 token 显示出来。
- 目录不可写、空间不足、元数据无效等错误不提供无限重试；按 `AppError.retryable` 决定是否显示重试。

**键盘**

初始焦点在版本单选组第一项；方向键切换版本，Tab 到目录更改、空间说明、取消按钮。安装开始后焦点不自动跳到取消按钮，避免误触；用户可 Tab 到取消。Esc 关闭文件选择框或说明弹层，但**永远不直接取消安装**。

**预览**：[install.svg](../../resources/mockups/install.svg)。预览展示“下载中、总量未知”的状态，所有版本、目录、空间和字节数均为设计示例。

### 3.3 设置

**目标**：用少量分组完成 Java、内存、游戏目录和启动后行为设置；错误在字段附近说明，保存前不写配置。

**信息层次**

1. Java：自动选择 / 手动路径；显示探测结果（版本、架构、来源）；手动路径无效时在字段下方说明并给出重新检测。
2. 内存：当前上限、允许范围、推荐值；单位 MB。
3. 游戏目录：当前路径、更改入口；说明会影响哪些实例由 application 检查，UI 不自行判断冲突。
4. 启动后行为：保持启动器打开 / 启动后关闭启动器；说明游戏进程独立运行。
5. 底部保存栏：未保存状态、校验摘要、恢复默认、保存。保存成功 / 失败在栏内反馈。

**Qt Widgets 分工**

| 区域 | 组件 | 说明 |
| --- | --- | --- |
| Java 模式 | `QGroupBox` + `QRadioButton` × 2 | 自动 / 手动；整组可用键盘方向键切换 |
| 手动路径 | `QLineEdit` + `QPushButton` | 浏览打开 `QFileDialog`；路径由 application 校验，UI 不判断版本 / 架构 |
| Java 结果 | `StatusPill` + `QLabel` | 由快照提供“已检测 / 未检测 / 无效 / 架构不符”等稳定状态 |
| 内存 | `QSpinBox`（后缀 ` MB`） | 范围、步长、默认值由快照提供；不用自由文本 |
| 游戏目录 | 只读 `QLineEdit` + `QPushButton` | 路径可选中复制；更改后由 application 校验 |
| 启动后行为 | `QGroupBox` + `QRadioButton` × 2 | 两个选项，不用复选框表达互斥行为 |
| 保存栏 | `PrimaryActionBar` | `保存` 主按钮、`恢复默认` 次按钮、状态文字 |
| 字段错误 | `FieldRow` 内联错误 | 不把错误集中到页面顶部；保存失败时聚焦第一个无效字段 |

**交互规则**

- 页面打开时加载快照；用户修改只写入本地草稿，不自动保存。
- 保存前由 application 校验草稿；失败时保留草稿、显示内联错误、不关闭页面。
- `Ctrl+S` 在设置页保存（仅当有修改且无保存中任务）；Esc 不静默丢弃修改，关闭页面或切换页面时若有未保存修改，显示“放弃更改 / 继续编辑”确认。
- 手动 Java 路径只在保存成功后生效；未保存的路径不用于启动。
- 内存范围不硬编码，避免 UI 复制系统内存规则；`QSpinBox` 的上下限、步长和推荐值全部来自快照。
- 恢复默认只重置当前页草稿，仍需用户确认保存；由 application 决定默认值。

**键盘**

初始焦点在 Java 模式第一项；Tab 顺序与视觉顺序一致（Java 模式 → 手动路径 / 浏览 → 内存 → 游戏目录 → 启动后行为 → 恢复默认 → 保存）。单选框用方向键切换，SpinBox 用上下键 / PageUp / PageDown，保存按钮用 Enter / Space。所有字段有可见标签与 `setBuddy` 关联。

### 3.4 日志与错误

**目标**：先告诉用户“发生了什么、我能做什么”，再提供可导出的脱敏日志；不把原始堆栈和凭据放在首屏。

**信息层次**

1. 错误摘要：用户能理解的原因、影响范围、下一步；不使用“未知异常”作为唯一说明。
2. 操作区：可重试时“重试”；始终提供“导出脱敏日志”；必要时“打开日志文件夹”。
3. 详情：稳定错误码、阶段、任务 ID、安全上下文（脱敏后的路径 / 版本）；默认折叠或弱化。
4. 日志正文：只读、可选择、等宽字体；按时间显示，已脱敏。
5. 空状态：没有错误时说明“最近没有错误”，仍可查看日志；没有日志时给出下一步。

**Qt Widgets 分工**

| 区域 | 组件 | 说明 |
| --- | --- | --- |
| 错误摘要 | `InlineNotice` / `SectionCard` | 标题、原因、下一步；`error` 语义 |
| 操作 | `QPushButton` | 重试（仅 `retryable`）、导出、打开文件夹 |
| 详情 | `QLabel` / 可折叠 `QFrame` | 错误码、阶段、`taskId`；不展示 token、完整命令行或凭据 |
| 日志 | `QPlainTextEdit`（只读） | `Cascadia Mono` / `Consolas`；自动换行；可复制 |
| 过滤 | 暂不进入 MVP 必需范围 | 如后续增加，只做严重级别筛选，不改日志内容 |
| 导出 | `QFileDialog` + application 命令 | UI 只选目标路径；application 负责脱敏和写文件 |

**日志行为**

- 日志更新随快照 / 通知到达，不轮询文件、不持续刷新。
- 用户停留在底部时自动跟随；用户向上滚动后停止跟随，并显示“回到最新”入口，避免阅读时被拉走。
- 日志文本本身已由 application 脱敏；UI 不再拼接请求头、令牌或认证 URL。
- 导出失败在操作区显示原因和可执行的下一步，不覆盖已有文件除非用户确认。
- 错误摘要与日志使用同一 `taskId` / 错误码关联；过期任务的错误不覆盖当前任务。

**键盘**

初始焦点在日志视图；PageUp / PageDown / Ctrl+Home / Ctrl+End 滚动，Ctrl+C 复制选中文本；Tab 到重试、导出、打开文件夹。错误摘要出现时通过可访问性事件播报，但不强行抢焦点。

## 4. 状态映射

### 4.1 主按钮

主按钮文案只由 `HomeSnapshot.primaryAction`（建议字段，待 Codex 确认）映射。UI 不根据账号、实例、Java 三个布尔值自行推导下一步。

| `primaryAction`（建议） | 文案 | 触发行为 | 显示条件 | 备注 |
| --- | --- | --- | --- | --- |
| `SignIn` | 登录 | 启动微软账号流程 | 未登录 | 不在 UI 嵌入浏览器运行时 |
| `Install` | 安装游戏 | 进入安装页 / 开始安装 | 已登录、无就绪实例 | 默认推荐版本由 application 给出 |
| `PrepareEnvironment` | 准备环境 | 获取或选择 Java 运行时 | 实例需要环境、Java 未就绪 | 先说明将下载的运行时和位置 |
| `Launch` | 启动游戏 | 调用启动用例 | 账号、实例、环境全部就绪 | 启动器可关闭，游戏继续运行 |
| `Retry` | 重试 | 重试当前可恢复任务 | 最近错误 `retryable == true` | 由 application 创建新任务 |
| `None` | 不显示主按钮 | — | 没有安全可执行动作 | 显示错误说明和“查看日志”，不编造操作 |

忙碌与终态：

| 场景 | 主按钮 | 次操作 | 说明 |
| --- | --- | --- | --- |
| 登录中 | “正在登录…”禁用 | 取消登录（若应用支持） | 不显示旧账号为已登录 |
| 安装中 | “安装中…”禁用 | 安装页“取消安装” | 主按钮不重复触发任务 |
| 准备环境中 | “准备环境中…”禁用 | 取消（若可取消） | 显示阶段，不显示虚构百分比 |
| 启动中 | “启动中…”禁用 | 查看日志 | 启动不是安装，不重新安装 |
| 游戏运行中 | “游戏运行中”禁用 | 查看日志 | MVP 不提供结束游戏 |
| 取消请求中 | “正在取消…”禁用 | 无 | 只有快照确认后才显示“已取消” |
| 已取消 | “继续安装” | 查看日志 | 复用缓存，由 application 决定 |
| 错误且可重试 | “重试” | 查看日志 | 不自动无限重试 |
| 错误且不可重试 | 无主按钮 | 查看日志 / 更改目录 | 给出具体下一步，不用“重试”掩盖 |

### 4.2 取消状态

| 任务状态（快照） | 取消按钮 | 文案 | 规则 |
| --- | --- | --- | --- |
| `Planning` / `Preparing` / `Downloading` / `Verifying` 且 `cancellable` | 可用 | 取消安装 | 点击后进入 `Cancelling`，按钮立即禁用 |
| `Cancelling` | 禁用 | 正在取消… | 不重复发送取消；等待工作线程退出和清理 |
| `Committing` 或 `cancellable == false` | 禁用 | 取消不可用 | tooltip / 旁注“正在完成安装” |
| `Succeeded` | 隐藏 | — | 只代表安装就绪；启动状态另管 |
| `Failed` | 隐藏 | — | 显示重试（若可重试）和日志 |
| `Cancelled` | 隐藏 | — | 显示“继续安装”，重新规划并检查缓存 |

取消安装**不做二次确认弹窗**：它是可恢复操作，弹窗只会增加新手负担。但取消按钮不能与主按钮相邻到容易误触，且点击后必须显示“正在取消”，不能先显示“已取消”。

### 4.3 错误展示

错误码分类是建议，最终以 Codex 提供的稳定错误码为准。UI 负责“错误码 → 中文文案”的映射，`retryable` 由 `AppError` 给出，UI 不解析消息文本。

| 错误类别（建议） | 展示位置 | 首屏文案重点 | 可用动作 |
| --- | --- | --- | --- |
| `Auth.*` | 首页账号区 / 日志 | 登录已过期或授权失败；需要重新登录 | 重新登录；不显示 token 细节 |
| `Network.*` | 安装 / 日志 | 网络中断或超时；已下载内容保留 | 可重试时“重试”，遵守应用的重试上限 |
| `Disk.*` | 安装 / 设置 | 空间不足或路径不可用；显示需要 / 可用 | 更改目录、释放空间；不自动重试 |
| `Permission.*` | 安装 / 设置 | 目录无写权限；给出具体路径 | 更改目录；不显示系统原始异常 |
| `Metadata.*` | 安装版本区 | 版本信息无效或不完整；不能开始安装 | 刷新版本列表；不猜测兼容性 |
| `Integrity.*` | 安装 / 日志 | 文件校验未通过；可复用部分保留 | 重试从缓存开始；不承诺断点续传 |
| `Launch.*` | 首页 / 日志 | 游戏未能启动；查看脱敏日志 | 重试启动（若应用允许）、导出日志 |
| `Unknown` | 日志 | 通用说明 + 错误码 + 任务 ID | 导出日志；不显示原始异常全文 |

错误详情中允许出现：错误码、阶段、`taskId`、脱敏路径、版本标签。禁止出现：访问令牌、认证 URL 中的凭据、完整启动命令行、用户隐私目录的未脱敏内容。

### 4.4 文案与焦点

- 主按钮使用动词开头：“登录”“安装游戏”“准备环境”“启动游戏”“重试”“继续安装”。
- 取消进行中使用“正在取消…”，完成使用“已取消”；二者不能混用。
- 错误标题说明“发生了什么”，正文说明“下一步”，不把技术名词放在标题。
- 状态变化通过文字 + 图标 + 可访问性事件表达；不只用颜色或动画。
- 主按钮禁用时，旁边必须有一句原因（例如“正在完成安装，无法取消”），不能只变灰。

## 5. 键盘与 100 / 150 / 200% 缩放验收

本节是 Qt UI 实现后的验收方案。本批只有设计稿和 SVG，**没有执行运行时缩放、键盘或可访问性验收**。

### 5.1 键盘

全局：

- 所有交互控件可仅用键盘到达和操作；Tab / Shift+Tab 顺序与视觉顺序一致，不出现焦点陷阱。
- 焦点环 2 px、对比度 ≥ 3:1，任何控件获得焦点都可见；不依赖鼠标悬停才显示操作。
- Enter / Space 激活按钮；方向键在单选组、导航列表、下拉框之间移动；Esc 只关闭弹层 / 对话框，不执行取消安装、退出账号或丢弃设置。
- 页面切换后焦点落在新页面第一个有意义的控件；不把焦点丢到窗口外。
- 长中文路径可通过只读输入框选择复制，或通过 tooltip 查看完整值；不因省略号丢失唯一信息。
- 错误出现时通过可访问性事件播报摘要，但不强行把焦点从用户当前控件抢走。

分页要点：

| 页面 | 初始焦点 | 关键路径 | 禁止 |
| --- | --- | --- | --- |
| 首页 | 可用主按钮 | Tab → 设置 / 其他版本 → 日志 | 不在无确认时触发退出账号 |
| 安装 | 版本单选组 | 方向键选版本 → Tab 到目录 → Tab 到开始 / 取消 | 安装中不自动聚焦取消；Esc 不取消 |
| 设置 | Java 模式 | 字段顺序 → 保存；`Ctrl+S` 保存 | Esc 不静默丢弃修改 |
| 日志 | 日志视图 | PageUp / PageDown / Ctrl+C → Tab 到导出 | 自动滚动不打断向上阅读 |

### 5.2 缩放

验收机：Windows 10 / Windows 11 x64，1920 × 1080，分别设置 100%、150%、200% 显示缩放；记录 Qt 版本、显卡与窗口实际逻辑 / 物理尺寸。

| 缩放 | 预期逻辑工作区（参考） | 布局预期 | 必查项 |
| --- | --- | --- | --- |
| 100% | 1920 × 1080 | 默认 1120 × 720；双列卡片；首页无需滚动 | 文字不裁切；主按钮 44 px；焦点环完整 |
| 150% | 1280 × 720 | 窗口钳制到可用工作区；宽度 ≥ 1120 时仍双列，高度不足时内容纵向滚动 | 固定底栏始终可见；无横向滚动条；中文路径不溢出 |
| 200% | 960 × 540 | 窗口约 880 × 470；单列卡片；纵向滚动 | 标题、按钮、状态文字不重叠；对话框完整可见；图标清晰 |

实现要求：

- 不关闭 Qt 6 的高 DPI 缩放；使用逻辑像素和 `QFontMetrics` 计算省略，不写死像素高度。
- 图标优先使用 SVG 并通过 `QIcon` 缩放；不准备多套位图，避免 200% 模糊。
- 所有固定高度控件使用 `minimumSizeHint` / `sizeHint`，在 200% 下允许增高；卡片不因文字变大而裁切。
- 主操作栏固定在滚动区外，200% 下仍可见；内容可滚动，不把主按钮推到屏幕外。
- 多显示器不同缩放之间移动窗口后，重新检查字体、边框和图标；Qt 每屏 DPI 变化不得导致布局错位。

## 6. 后续所需 application 接口清单

**现状**：仓库中没有 `src/application`，也没有 `TaskSnapshot`、`AppError` 的真实头文件。下面全部是 UI 对 application 的**需求清单与建议命名**，用于 Codex 设计真实接口；不代表这些类型或方法已经存在。确认真实头文件与 Qt/MSVC 可构建后，才在 `src/ui` 写 C++。

### 6.1 只读快照

所有快照按值传递、只读、在主事件线程交付；UI 不持有可变业务对象的引用。

| 快照（建议名） | 最小字段 | 用途 / 约束 |
| --- | --- | --- |
| `HomeSnapshot` | `account`、`instance`、`environment`、`primaryAction`、`primaryActionEnabled`、`blockingReasonCode`、`activeTask`、`launchSummary` | 首页一次渲染；主操作由 application 推导 |
| `AccountSnapshot` | `state`（未登录 / 登录中 / 已登录 / 已过期 / 错误）、`displayName` | 不包含 token；显示名可为脱敏值 |
| `InstanceSnapshot` | `stableId`、`displayName`、`versionLabel`、`readiness`（缺失 / 安装中 / 就绪 / 不完整） | 版本标签是展示值，不在 UI 解析 |
| `EnvironmentSnapshot` | Java 状态（缺失 / 就绪 / 手动无效 / 检测中）、版本标签、架构标签、来源（自动 / 手动） | Java 兼容判断在 core / application |
| `LaunchSummary` | `memoryMb`、`closeLauncherAfterLaunch`、`lastLaunchState`（可选） | 首页摘要；值来自设置 / 启动用例 |
| `TaskSnapshot` | `taskId`、`kind`、`instanceId`、`state`、`phase`、`phaseIndex` / `phaseCount`、`completedBytes`（可选）、`totalBytes`（可选）、`cancellable`、`error`（可选） | 安装 / 准备任务；`totalBytes` 为空表示未知，UI 不猜 |
| `AppError` | 稳定 `code`、`phase`、`retryable`、安全上下文（脱敏键值）、`taskId` / `logRef` | UI 用 `code` 映射文案；不解析异常文本 |
| `VersionCatalogSnapshot` | 加载状态、`recommendedVersionId`、版本条目列表、错误 | 条目含 `id`、`label`、`channelLabel`、`verified`、可选 `javaRequirementLabel`（仅展示） |
| `InstallTargetSnapshot` | 展示路径、是否有效、`requiredBytes`（可选）、`freeBytes`（可选）、错误 | 目录由 application 校验；未知值明确为空 |
| `SettingsSnapshot` | Java 模式、手动路径、探测结果、内存当前 / 最小 / 最大 / 步长、游戏目录、启动后行为 | 范围与默认值来自 application，不在 UI 硬编码 |
| `LogSnapshot` | 错误摘要（可选）、日志条目（`severity`、`time`、`message`，已脱敏）、是否可导出 | UI 只显示与导出，不读原始日志文件 |

补充要求：

- `TaskSnapshot` 的每次通知都带 `taskId`；UI 在取消、重试、切换实例后忽略旧 ID。
- `TaskSnapshot` 不持久化运行中状态作为恢复依据；UI 冷启动不根据旧“成功”文案推断就绪。
- `AppError.code` 是稳定标识；新增错误码时 UI 有兜底文案，不崩溃。
- 未知枚举值必须可处理：显示“状态未知”+ 原始代码，记录诊断，不静默当作成功。
- 快照中的路径、版本、账号名均为展示安全值；凭据、token、完整认证 URL 不进入 UI。

### 6.2 命令 / 用例

命令应快速返回，结果通过快照或信号回传；UI 线程不执行阻塞 I/O、网络、校验或解压。

| 目的 | 建议方法（待确认） | 说明 |
| --- | --- | --- |
| 首页主操作 | `invokePrimaryAction()` | application 根据当前状态决定调用登录 / 安装 / 准备 / 启动；避免 UI 复制分支 |
| 登录 / 登出 / 刷新 | `signIn()`、`signOut()`、`refreshSession()` | 走系统浏览器或经验证的官方流程；登出清理凭据 |
| 版本目录 | `loadVersionCatalog()`、`selectVersion(id)` | 选择只是草稿；不触发安装 |
| 目录校验 | `validateInstallTarget(path)` | UI 打开 `QFileDialog`，但路径规范化、权限、空间判断在 application |
| 开始安装 | `startInstall(InstallRequest)` → `taskId` | 请求含版本、目录、实例显示名；重试复用同一入口，由 application 检查缓存 |
| 取消任务 | `cancelTask(taskId)` | 只进入 `Cancelling`；不强行终止线程 |
| 启动游戏 | `startLaunch(instanceId)` | 与安装任务分离；启动器关闭不结束游戏 |
| 设置读取 | `loadSettings()` | 页面打开时取快照 |
| 设置校验 | `validateSettings(draft)` | 返回字段级错误；UI 不判断 Java / 内存规则 |
| 设置保存 | `saveSettings(draft)` | 单一写入入口；成功后回传新快照 |
| Java 路径校验 | `validateJavaPath(path)` | 探测版本与架构由 application 完成 |
| 日志读取 | `loadLogs()` | 返回已脱敏日志快照 |
| 导出日志 | `exportLogs(destinationPath)` | UI 只选目标路径；application 执行脱敏与写入 |
| 打开日志目录 | `openLogFolder()` | 由 application / 平台层执行，UI 不拼系统路径 |
| 关闭窗口 | `requestShutdown()` → `shutdownReady()` | 有安装任务时先协作取消；UI 收到就绪后再关闭 |

信号建议：`homeChanged(const HomeSnapshot&)`、`taskChanged(const TaskSnapshot&)`、`catalogChanged(...)`、`installTargetChanged(...)`、`settingsChanged(...)`、`logsChanged(...)`、`errorRaised(const AppError&)`、`shutdownReady()`。全部使用排队连接交付到 UI 线程。

### 6.3 契约要求

- application 是任务状态唯一写入者；UI 只读快照，不维护第二份“安装中”布尔值。
- 取消、重试、切换实例后，旧 `taskId` 的通知必须可识别并忽略；不能靠“最后一条通知”猜当前任务。
- 取消请求只进入 `Cancelling`；`Cancelled` 必须在工作线程退出和清理后才发出。
- `AppError.retryable` 由 application 决定；网络瞬态错误可有上限退避，磁盘不足 / 无权限 / 无授权不可无限重试。
- 登录过期、登出后旧回调不得重新保存凭据；UI 不接触凭据。
- 安装与游戏运行状态分开；游戏退出不得触发重新安装。
- 快照不携带凭据；错误、日志、导出内容统一脱敏。
- UI 文案由 UI 侧统一维护（错误码 → 中文、阶段 → 中文）；application 不返回最终用户长句，避免文案散落。

### 6.4 需要 Codex 确认 / 提供

在以下事项确认前，本批不写 `src/ui`：

1. `TaskSnapshot`、`AppError` 的真实头文件、字段、枚举与生命周期；`totalBytes` 是否可为空、如何表达“未知”。
2. `HomeSnapshot` / `PrimaryAction` 是否由 application 直接给出；首页主按钮如何避免 UI 重复推导。
3. 版本目录接口：推荐版本、`verified` 的语义、是否提供 Java 要求展示值。
4. 安装目标校验接口：路径规范化、权限、空间、所需字节是否可提前给出。
5. 设置草稿 / 校验 / 保存接口，以及 Java 探测结果的状态枚举。
6. 日志读取、脱敏与导出接口；UI 是否允许直接打开日志目录。
7. Qt / MSVC 的 CMake 目标名、Qt 模块（Widgets、Svg 是否可用）、构建与测试命令；确认可编译后再写控件。
8. 信号线程归属、对象生命周期、关闭窗口时的协作取消契约。
