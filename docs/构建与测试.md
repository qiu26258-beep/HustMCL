# 构建与测试

当前构建仅包含无 Qt 依赖的 `hustmcl_core` 静态库与测试，不是游戏启动器。前端由 DSH 中的 DeepSeek 实施，Qt Widgets / MSVC 构建在后续批次接入。

## 已验证环境

2026-10-21 本机：Windows x64，w64devkit GCC 16.2.0（`x86_64-w64-mingw32`）、CMake 4.4.2、Ninja 1.13.2、Python 3.12.10。GCC 仅用于无 Qt 核心的开发验证；不要将其产物与 MSVC Qt DLL 混用。目标发行工具链仍为 MSVC x64，精确 Qt、MSVC 与 SDK 版本在安装及实测后登记。

最低构建工具要求：CMake 3.24、C++20、Python 3.10（仅测试）。配置会拒绝非 Windows、32 位与 ARM64 编译目标；这不代表已验证 Windows 10 的最低构建号。

## 本地命令

```powershell
cmake --preset core-debug
cmake --build --preset core-debug
ctest --preset core-debug

cmake --preset core-release
cmake --build --preset core-release
ctest --preset core-release
```

Presets 使用当前环境的编译器，不写死本机路径。MSVC 使用 x64 开发者终端；切换编译器时使用新的构建目录，不能复用 GCC 缓存。个人机器路径放入忽略的 `CMakeUserPresets.json`，依赖安装目录使用 `.deps/`，产物使用 `build/` 或 `out/`。

只构建核心、不配置 Python 测试入口：

```powershell
cmake -S . -B build/core-only -G Ninja -DBUILD_TESTING=OFF
cmake --build build/core-only
```

## 测试覆盖与边界

| CTest | 检查 |
| --- | --- |
| core.java_runtime | 按元数据给定的主版本选 x64 Java；无 Java、版本不符、错误架构、空路径、手动选择优先且不静默回退；保留中文与空格路径 |
| architecture.core_includes | 核心只能引用自身、明确允许的标准值类型头文件和 Qt Core 值类型头文件 |
| architecture.include_guard_regression | 构造 UI、网络、平台、I/O、跨层与宏 include 输入，确认检查会拒绝；注释中的示例不误判 |
| architecture.forbidden_link | 实际配置一个错误链接 Qt6::Widgets 的小工程，断言因指定依赖诊断失败；不把任意配置失败当作成功 |

Java 选择函数只处理已经探测好的描述，既不访问磁盘也不执行 Java。路径存在、实际版本 / 架构、游戏版本元数据解析、获取运行时和启动游戏均尚待实现。默认只接受所需主版本的精确匹配，不能把更高主版本自动视为兼容；候选优先顺序由调用方明确提供。

源文件 include 检查与 CMake 链接检查共同约束依赖，不能证明所有 C++ 代码没有副作用，也不能替代审查。新增标准 / Qt 值类型头文件时同步说明允许理由与回归场景；不要通过全局 include 路径绕过边界。

测试通过 CTest 执行，不依赖 `assert`，Release 同样运行真实断言。当前没有使用 Qt Test，因为这一批核心无需 Qt；接入 Qt 用例与界面时再增加对应目标。真实账号、网络、游戏与系统验收另记结果。
