# 构建与测试

当前仓库包含两条构建路径：

- 默认核心构建：无 Qt 依赖的 `hustmcl_core` 静态库与离线 CTest。
- 可选桌面演示：`HUSTMCL_BUILD_DESKTOP=ON` 时构建 `src/application`、`src/ui`、`src/app` 和 Qt Widgets 演示程序。桌面演示使用样例数据，不是完整启动器。

## 已验证环境

2026-10-21 本机：

| 用途 | 环境 |
| --- | --- |
| 核心构建 / CTest | Windows x64、w64devkit GCC 16.2.0、CMake 4.4.2、Ninja 1.13.2、Python 3.12.10 |
| Qt 桌面演示 | Qt 6.10.3 MinGW 组件、配套 GCC 13.1（`D:/HustMCL/.deps/Qt/Tools/mingw1310_64`）、CMake 4.4.2、Ninja 1.13.2 |
| MSVC | 尚未安装验证；不把 MinGW 产物与 MSVC Qt DLL 混用 |

最低构建工具要求：CMake 3.24、C++20、Python 3.10（仅测试）。配置会拒绝非 Windows、32 位与 ARM64 编译目标；这不代表已验证 Windows 10 的最低构建号。

## 核心构建（默认）

```powershell
cmake --preset core-debug
cmake --build --preset core-debug
ctest --preset core-debug

cmake --preset core-release
cmake --build --preset core-release
ctest --preset core-release
```

`HUSTMCL_BUILD_DESKTOP` 默认 `OFF`，核心 preset 不查找 Qt，不引入 Widgets / Network / Win32。只构建核心、不配置测试入口：

```powershell
cmake -S . -B build/core-only -G Ninja -DBUILD_TESTING=OFF
cmake --build build/core-only
```

## Qt 桌面演示

### 配置与构建

先把配套 MinGW 与 Qt 的 `bin` 放到本次进程 PATH 最前面，避免 PATH 中的 GCC 16.2 与预编译 Qt 混用：

```powershell
$env:PATH = "D:\HustMCL\.deps\Qt\Tools\mingw1310_64\bin;D:\HustMCL\.deps\Qt\6.10.3\mingw_64\bin;$env:PATH"
cmake -S . -B build/desktop-debug -G Ninja `
  -DHUSTMCL_BUILD_DESKTOP=ON `
  -DBUILD_TESTING=ON `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_CXX_COMPILER=D:/HustMCL/.deps/Qt/Tools/mingw1310_64/bin/g++.exe `
  -DCMAKE_PREFIX_PATH=D:/HustMCL/.deps/Qt/6.10.3/mingw_64
cmake --build build/desktop-debug
ctest --test-dir build/desktop-debug --output-on-failure
```

目标结构：

| 目标 | 内容 |
| --- | --- |
| `hustmcl_core` | 现有核心规则；不链接 Qt Widgets |
| `hustmcl_application` | 页面需要的最小值类型快照与 `FrontendGateway` 契约；Qt Core |
| `hustmcl_ui` | 原生页面、共用组件、QSS、共享 JPEG 的 qrc 资源；Qt Widgets |
| `hustmcl_desktop_core` | `MainWindow`、显式演示控制器，不含 `main` |
| `hustmcl_desktop` | Windows GUI 子系统的可执行入口、命令行截图与演示场景；`qt_add_executable(... WIN32 ...)` 提供 Qt 入口并避免双击时出现控制台 |
| `hustmcl_ui_tests` | Qt Test；控制台子系统，仅 `BUILD_TESTING` 时构建 |

可执行文件：

```text
build/desktop-debug/src/app/hustmcl_desktop.exe
```

`find_package(Qt6 6.10 REQUIRED COMPONENTS Widgets)` 只在桌面开关开启时执行；`Qt6::Test` 只在 `BUILD_TESTING` 时查找。qrc 中只有一份共享 JPEG：`resources/mockups/oil-ui/assets/xiaoke-campus.jpg`，运行时通过 `:/brand/xiaoke-campus.jpg` 加载并由 `QPixmapCache` 缓存解码。

### 演示场景与截图

可用场景：`home-ready`、`install-unknown`、`install-known`、`install-cancelling`、`install-cancelled`、`install-committing`、`install-failed`、`install-long-path`。

启动器是 GUI 子系统，PowerShell 的 `&` 不会等待它完成，也不保证捕获它的 stdout / 退出码。截图脚本应使用 `Start-Process -Wait`（或 `cmd /c`）；这样重定向输出和非零退出码仍然有效：

```powershell
$env:PATH = "D:\HustMCL\.deps\Qt\Tools\mingw1310_64\bin;D:\HustMCL\.deps\Qt\6.10.3\mingw_64\bin;$env:PATH"
$env:QT_QPA_PLATFORM = "offscreen"
$exe = (Resolve-Path "build/desktop-debug/src/app/hustmcl_desktop.exe").Path
$p = Start-Process -FilePath $exe -Wait -PassThru `
  -ArgumentList @("--scenario","install-unknown","--page","install",
                  "--scale","1","--window-size","1120x720",
                  "--screenshot","out/native-ui-review/install-unknown-1x.png") `
  -RedirectStandardOutput "out/native-ui-review/install-unknown-1x.stdout.txt" `
  -RedirectStandardError "out/native-ui-review/install-unknown-1x.stderr.txt"
if ($p.ExitCode -ne 0) { throw "capture failed: $($p.ExitCode)" }
```

离屏 1.5x / 2x 用同一入口，只替换 `--scale 1.5` / `--scale 2` 与输出路径；离屏 1x 仍由 `--scale 1` + `QT_QPA_PLATFORM=offscreen` 得到。

离屏模式会自动把 `QT_QPA_FONTDIR` 指向 `C:\Windows\Fonts`，否则 Qt basic offscreen 字体库可能无法渲染中文。离屏截图用于可重复的布局与缩放检查，不包含 Windows 原生标题栏。

`--scale` 是提供给 Qt 的缩放提示，不是跨平台绝对 DPI，也不会关闭 Qt 高 DPI 缩放。Windows 原生平台仍使用本机系统缩放；本机系统为 150%，所以原生客户区截图是 1680 × 1080 / DPR 1.5，不能用 `--scale 1` 期待原生 1120 × 720。离屏基础 1x / 1.5x / 2x 与原生 150% 必须分开记录。

真实 Windows QPA 运行（不带 `QT_QPA_PLATFORM=offscreen`）可抓客户区，同样通过 `Start-Process -Wait`：

```powershell
$p = Start-Process -FilePath $exe -Wait -PassThru `
  -ArgumentList @("--scenario","home-ready","--page","home",
                  "--window-size","1120x720",
                  "--screenshot","out/native-ui-review/home-native.png")
$p.ExitCode
```

`--native-screenshot` 通过 `QScreen::grabWindow` 抓已显示窗口；Windows 标题栏属于非客户区，Qt 的客户区截图不包含它。完整窗口标题栏用系统级截图单独记录。截图、临时分析都在忽略目录 `out/native-ui-review/`，不提交。

### Qt Test 覆盖

`ctest --test-dir build/desktop-debug --output-on-failure` 当前包含 4 项核心测试和 1 项 `desktop.ui_tests`（14 个测试函数）。测试在 `initTestCase` 中应用与程序一致的 Fusion 样式、`theme::baseFont()` 和 `theme::styleSheet()`，长路径与可见性检查因此对应实际界面。

- 页面导航与页面信号；
- `HomeSnapshot` 直接驱动主按钮文字 / enabled，UI 不由账号、Java、实例布尔值推导；
- 未知总量 / 非正总量不出现 `%`，进度控件隐藏；
- 已知总量显示进度和百分比；
- 极大完成量饱和到 100%，负完成量归零，正常比例的百分比和进度条一致；
- 准备环境 / 校验 / 下载 / 提交阶段的失败文案来自同一个阶段映射；
- 取消请求先进入“正在取消…”，只有应用确认后才显示“已取消”；
- 提交窗口取消按钮禁用；
- 失败可重试、重试生成新 `taskId`，旧任务完成不会覆盖新任务；
- 长中文路径省略并保留 tooltip；
- 重复 `setSnapshot` / render 不增长控件树，共享 JPEG 从 `QPixmapCache` 复用；
- 无装饰模式隐藏首页 / 侧栏插画与说明；
- 设置 / 日志导航禁用且有说明。

进度归一化集中到 `copy::progressFraction()`，结果先限制在 `[0, 1]`，再换算到百分比或进度条 0–1000；非正总量和负完成量不产生负数或未定义转换。阶段标题、描述、编号和失败文案集中在 `install_stages.*`，`StageList` 与 `InstallPage` 不再各自维护映射。

这些是演示状态与展示测试，不是真实下载器、认证或游戏启动集成测试。

## 测试边界

核心 Java 选择函数只处理已经探测好的描述，既不访问磁盘也不执行 Java。路径存在、实际版本 / 架构、游戏版本元数据解析、获取运行时和启动游戏均尚待实现；默认只接受所需主版本的精确匹配，不能把更高主版本自动视为兼容。

源文件 include 检查与 CMake 链接检查共同约束核心依赖，不能证明所有 C++ 代码没有副作用，也不能替代审查。新增标准 / Qt 值类型头文件时同步说明允许理由与回归场景；不要通过全局 include 路径绕过边界。

桌面演示没有真实微软登录、版本目录、Java 获取、下载校验、安装或游戏启动；设置与日志页未实现。Codex 已完成下述 Release 本地演示部署与干净 PATH 启动。Windows 10/11 干净系统验收、MSVC 和正式发布验证仍需后续完成。DSH 收尾复核见[前端验证记录](frontend/验证记录.md)第 9.1 节。

## Release 本地演示部署

2026-10-21，Codex 在 DeepSeek 提交 `7410056` 后独立复验：Debug / Release 均 5/5 CTest 通过，Qt UI 包含 14 个测试函数。关闭测试并显式禁用查找 Qt6Test / Python3 时也能配置桌面目标，证明这两项不成为运行程序的构建依赖。Vulkan headers 未找到的提示不影响本批 Qt Widgets 构建与运行。

配套 PATH 同前文，Release 使用单独目录：

```powershell
cmake -S . -B build/desktop-release -G Ninja `
  -DHUSTMCL_BUILD_DESKTOP=ON -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_CXX_COMPILER=D:/HustMCL/.deps/Qt/Tools/mingw1310_64/bin/g++.exe `
  -DCMAKE_PREFIX_PATH=D:/HustMCL/.deps/Qt/6.10.3/mingw_64
cmake --build build/desktop-release --parallel 2
ctest --test-dir build/desktop-release --output-on-failure

New-Item -ItemType Directory -Force out/HustMCL | Out-Null
Copy-Item build/desktop-release/src/app/hustmcl_desktop.exe out/HustMCL/hustmcl_desktop.exe -Force
& .deps/Qt/6.10.3/mingw_64/bin/windeployqt.exe `
  --release --compiler-runtime --no-translations `
  --skip-plugin-types generic,networkinformation,tls --no-system-dxc-compiler `
  out/HustMCL/hustmcl_desktop.exe
```

本演示不使用 TUIO、网络信息或 TLS 插件，跳过这些插件避免连带部署未使用的 Qt Network。保留 Qt Core / Gui / Widgets、Windows 平台、JPEG 等图像格式、样式与配套 GCC 运行库；目录共 13 个文件、40,105,730 bytes（约 38.25 MiB）。本机只安装了 qtbase，未安装的 Qt 翻译目录会产生提示；本批不部署翻译，页面中文由程序提供。GCC 运行库由本次 PATH 中的配套 MinGW 13.1 取得。

独立启动验证使用进程级环境：PATH 仅为 Windows 的 System32 和 Windows 目录，移除 Qt 插件路径覆盖，设置 `QT_QPA_PLATFORM=windows`，从部署目录启动。首页与安装页分别使用 `--native-screenshot`，均退出 0、stderr 为空，截图为 1680 × 1080 / DPR 1.5；未使用离屏或 QWidget fallback。无效场景退出 2，stderr 输出错误，GUI 子系统仍支持显式等待进程和重定向。

这验证了本机部署目录启动，不能替代未安装 Qt 的干净 Windows 10/11、MSVC、安装器、性能、真实登录和游戏验收。图片与运行库留在整个部署目录中；生成目录不进入 Git。
